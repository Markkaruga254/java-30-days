# Contributing to Java 30

This is a practical learning log. Keep changes small, readable, and reproducible.

## Repository map
- `day-01/` … `day-30/`: lesson plan, daily log, and starter code.
- `leetcode/`: one `NNNN-kebab-case-title/` directory per problem, with `Solution.java` and `NOTES.md`.
- `weekly-reviews/`: one reflection template per week.
- `capstone/`: final project brief and CI guidance.
- `index.html` and `assets/`: the static GitHub Pages learning hub.

## Daily workflow
1. Read the day's plan before coding.
2. Type examples yourself; do not paste a complete solution.
3. Attempt the challenge independently.
4. Add tests when the curriculum calls for them.
5. Record what you learned, what failed, and how you fixed it.
6. Commit with a clear message, e.g. `feat(day-08): add generic repository exercise`.

Use Java 21 unless a lesson explains a compatibility reason. Keep early examples dependency-free. Never commit credentials, tokens, or local environment files.

## Progress tracking
The website stores checklists in this browser's local storage; it does not write progress to GitHub. Daily Markdown logs and LeetCode notes are the durable, reviewable record of your work.
